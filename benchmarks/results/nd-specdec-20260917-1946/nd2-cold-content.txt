Speculative decoding is a sophisticated inference optimization technique designed to mitigate the primary bottleneck in Large Language Model (LLM) serving: the sequential nature of autoregressive generation. In standard LLM inference, generating a single token requires a full forward pass through the massive transformer network. This process is heavily memory-bandwidth bound rather than compute-bound, meaning that the GPU’s powerful arithmetic units are often underutilized while waiting for data to move from High Bandwidth Memory (HBM) to the processing cores. Speculative decoding addresses this inefficiency by leveraging a smaller, faster "draft" model to propose multiple tokens at once, which are then verified in parallel by the larger, more accurate "target" model.

The architecture of speculative decoding relies on two distinct components: the draft model and the target model. The target model is the full-sized LLM (e.g., Llama-3-70B or Mistral-7B) that ensures high-quality, contextually accurate outputs. The draft model is a significantly smaller, lighter version of the same architecture (e.g., Llama-3-8B or a quantized variant) that shares the same tokenizer and vocabulary. Because the draft model has fewer parameters, its forward pass is much faster and less memory-intensive. The core intuition is that while the draft model is less accurate, it is often "good enough" to predict the next few tokens correctly. By generating a sequence of $k$ candidate tokens (the "speculation length") using the draft model, the system can then verify all $k$ tokens in a single forward pass of the target model.

The verification step is the critical mechanism that ensures the output quality matches that of the target model alone. When the draft model generates a sequence of $k$ tokens, the target model processes the original prompt plus these $k$ draft tokens in one go. Crucially, the target model computes the probability distribution for the next token at every position in the sequence. This allows the system to compare the draft model’s predictions against the target model’s ground truth probabilities.

The acceptance criteria are governed by a specific rejection sampling algorithm to ensure that the final output distribution is mathematically identical to what the target model would have produced if it had generated the tokens sequentially. For each position $i$ in the draft sequence, the system compares the probability assigned by the draft model ($p_{draft}$) and the target model ($p_{target}$). If $p_{target} \geq p_{draft}$, the token is accepted. If $p_{target} < p_{draft}$, the token is rejected with a probability of $1 - \frac{p_{draft}}{p_{target}}$. If a token is rejected, the system does not simply discard the rest of the draft; instead, it resamples a new token from the adjusted distribution of the target model, effectively correcting the error. This process continues until the first rejection occurs or the entire draft sequence is accepted. If the entire sequence is accepted, the system gains $k$ tokens in the time it would have taken to generate one, resulting in a significant speedup.

The latency impact of speculative decoding is profound but nuanced. In standard autoregressive decoding, the latency per token is dominated by the memory bandwidth required to load the target model’s weights. With speculative decoding, the cost of generating $k$ tokens is roughly the cost of one draft forward pass plus one target forward pass. Since the draft model is much smaller, its forward pass is negligible compared to the target model’s. Therefore, the total time to generate $k$ tokens is approximately equal to the time to generate one token in standard inference. This results in a theoretical speedup factor of $k$, provided that the acceptance rate is high. However, if the draft model is too dissimilar to the target model, the acceptance rate drops, and the system may spend more time verifying rejected tokens than it saves. Thus, the optimal $k$ depends on the similarity between the draft and target models and the specific input context.

The interaction with Key-Value (KV) caching is a crucial technical detail that enables this efficiency. In standard inference, the KV cache stores the keys and values for all previous tokens to avoid recomputation. In speculative decoding, the target model must compute the KV cache for the draft tokens to verify them. If a draft token is rejected, the KV cache entries for that token and all subsequent draft tokens must be discarded or rolled back. Modern serving frameworks handle this by maintaining a "speculative" KV cache buffer. When the target model verifies the draft, it writes the new KV entries into this buffer. If a token is accepted, the buffer is committed to the main KV cache. If rejected, the buffer is truncated. This rollback mechanism ensures that the KV cache remains consistent with the actual generated sequence, preventing context contamination.
